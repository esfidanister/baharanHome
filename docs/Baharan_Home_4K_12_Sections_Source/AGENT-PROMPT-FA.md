# دستور اجرایی برای Codex — پیاده‌سازی تصویری بهاران هوم

این بسته یک Design Handoff است. عکس‌های رندرشده‌ی `/png/`، فایل‌های HTML مستقل در `/html/`، توکن‌های CSS و SVGهای `/assets/` را بررسی کن.

## هدف

طراحی بصری باید از نظر هندسه، نسبت‌ها، گرید، تایپوگرافی فارسی، فاصله، رنگ، ریتم سکشن‌ها، خروج تصویر از قاب و رفتار ریسپانسیو به تصاویر مرجع نزدیک باشد. هیچ صفحه‌ای را فقط با دیدن تصویر کلی از صفر حدس نزن.

## مراحل اجباری

۱. اول پروژه واقعی WordPress/WooCommerce را ممیزی و Git Status و Backup را ثبت کن. هیچ محصول یا سفارش واقعی را تغییر نده.

۲. `sections.json` را بخوان و به ترتیب شماره سکشن را پیاده کن. برای هر سکشن HTML نمونه و تصویر PNG متناظر را بررسی کن؛ فایل HTML «وایرفریم نمایشی» است، نه تم WordPress آماده.

۳. هدر و مگامنو: کامپوننت‌های متمایز و قابل دسترس؛ اتصال جست‌وجو و سبد به WooCommerce؛ پیاده‌سازی RTL و موبایل.

۴. Hero و Bento: تصویر محصول بیرون از مرز رنگی باشد، اما نباید از کانتینر یا Viewport بیرون بزند. ساختار توصیه‌شده: parent با position:relative و overflow:visible، لایه رنگی داخلی با overflow:hidden یا mask/clip، و تصویر position:absolute در لایه هم‌سطح؛ برای تصاویر width/height و aspect-ratio اختصاص بده تا CLS رخ ندهد.

۵. دسته‌بندی: دسته‌های واقعی؛ برند: برندهای ثبت‌شده؛ کارت محصول: قیمت و تخفیف و امتیاز از داده واقعی؛ Empty State تمیز و قابل‌مدیریت.

۶. سکشن‌ها قابل جابه‌جایی، خاموش/روشن و تنظیم در پنل بهاران استودیو باشند؛ تنظیم متن، رنگ، تصویر دسکتاپ و موبایل، منبع محصولات، خروج تصویر، CTA، پس‌زمینه و Motion.

۷. تصویرهای `/assets/*transparent.png` صرفاً Illustration مرجع هستند؛ برای فروش کالای واقعی باید تصاویر مربوط به همان SKU جایگزین شوند. لوگوهای نامعتبر و وعده‌های تجاری تأییدنشده منتشر نشوند.

۸. هر سکشن را در ۳۶۰/۳۹۰/۴۳۰/۷۶۸/۱۰۲۴/۱۴۴۰/۱۹۲۰ تست کن؛ Playwright screenshot و visual diff ارائه بده. انیمیشن‌ها در reduced motion خاموش و Controls قابل استفاده با صفحه‌کلید باشند.

۹. فقط پس از تست عملکرد سبد، جست‌وجو، فیلتر، محصولات ساده/متغیر و خطاهای PHP/JS، خروجی ZIP نصب‌پذیر ارائه کن.

## نظام تطبیق با مرجع

- تقارن و تراز متن‌ها بر مبنای خطوط راهنما، نه بر اساس حدس.
- فرم‌ها و منحنی‌های هر سکشن مستقل ولی هم‌خانواده باشند؛ همه چیز را صرفاً rounded rectangle نساز.
- نسبت عکس محصول به سکشن و پیش‌آمدگی آن را طبق عکس و HTML مربوط به همان سکشن نگه دار.
- کارت محصول باید دیتای واقعی داشته باشد؛ برای تست از data fixtures جداگانه و غیرعمومی استفاده کن.
- در انتهای هر فاز، screenshot واقعی پیاده‌سازی شده، فایل‌های تغییر یافته، نتایج تست و مغایرت‌های بصری را گزارش بده.
